# V3: LightGBM с признаками истории и первым горизонтом

Экспериментальный CSV — `submissions/v3_tweedie_h1_600.csv`. Средний локальный score на 14 датах — **0,327937**. Новый контроль ещё не открыт; публичный результат неизвестен.

Модель воспроизводит решение участника **Vlado**: [исходный код](https://github.com/L3iHS/rwb-shipment-forecasting/blob/bd61c6d560f4a838dc436fbc13139fa42ccb99be/experiments/exp_gbm.py), commit `bd61c6d560f4a838dc436fbc13139fa42ccb99be`. Параметры сохранены в [конфигурации](../configs/v3_tweedie_h1_600.json).

## Модель

Один LightGBM прогнозирует восемь горизонтов с функцией потерь Tweedie 1.3: 600 деревьев, 63 листа, learning rate 0,05, seed 42. Модель получает 123 признака: историю объёмов и статусов, дневные и недельные профили, календарь, общую активность сети и оценки получасового объёма. `route_id` не используется как признак.

Нормализация и веса обучающих строк используют недельное среднее объёма. Пики в истории признаков ограничиваются границей, рассчитанной по предыдущим семи суткам; исходные значения обучающего таргета сохраняются. Для первого горизонта модель учит остаток после вычитания оценки уже прошедшего получаса и возвращает эту оценку в прогноз. Получасовой объём восстанавливается из истории, напрямую он не наблюдается.

Обучение использует источники за 42 дня, время источника — 08:00–13:00. Для признаков нужно как минимум 29 дней предшествующей истории. В каждом временном срезе все обучающие метки уже известны, предиктор получает только историю до момента прогноза. При недостаточной длине истории количество обучающих источников сокращается. Используются два вычислительных потока; исходный код автора задавал десять.

## Результаты

Ежедневные моменты прогноза: **18–31 октября 2025 года, 10:30**. Перед каждым прогнозом модель обучается заново. Основная метрика — среднее по датам `WAPE + |Relative Bias|`.

| Модель | Средний score | WAPE | Средний абсолютный bias |
|---|---:|---:|---:|
| `latent_mass_blend50` | 0,332570 | 0,317049 | 0,015522 |
| `mae_share_mass25` | 0,332149 | 0,316527 | 0,015622 |
| **`vlado_t_h1s600_reference`** | **0,327937** | **0,316184** | **0,011753** |

Улучшение относительно `mae_share_mass25` — **0,004212**, выигрыш на **11 из 14** дат. Все три ухудшения включены в среднее. Эти даты многократно использовались при разработке; они не являются новым независимым контролем. Порог 0,32 на полном наборе окон не достигнут.

## Воспроизведение

Установите зависимости из `requirements.txt`, включая `lightgbm==4.7.0`. Из корня проекта в Bash или Zsh:

```bash
python scripts/run_v3.py backtest --config configs/v3_tweedie_h1_600.json \
  --train data/raw/train_solo_track.parquet \
  --origins 2025-10-{18..31}T10:30:00 \
  --output-dir .local/reproduce/v3_development
```

Ориентиры воспроизводятся через `scripts/run_comparison.py` с конфигурациями `configs/mae_share_mass25.json` и `configs/latent_mass_blend50.json`, `--split research` и соответствующим `--models`.

Создание нового локального CSV для исходного test:

```bash
python scripts/run_v3.py submit --config configs/v3_tweedie_h1_600.json \
  --train data/raw/train_solo_track.parquet --test data/raw/test_solo_track.parquet \
  --output submissions/v3_tweedie_h1_600_reproduced.csv
```

Команда сопоставляет прогнозы с ID по маршруту и времени, проверяет формат и сохраняет метаданные рядом с CSV. Существующие файлы не перезаписываются. На платформу ничего не отправляется.

На локальном запуске с двумя потоками пик памяти процесса составил около **10,6 ГиБ**. Временные массивы признаков на диске удаляются после обучения. Проверки на сгенерированных данных:

```bash
python -m pytest -q tests/test_v3_features.py tests/test_v3_boosting.py tests/test_v3_cli.py
RWB_V3_NATIVE_TESTS=1 python -m pytest -q tests/test_v3_boosting.py
```
