# Первый ML-аудит Colhound

Дата: 08.11.2026. Статус: выполнено сравнение сохранённых прогнозов и замер CPU-сервиса; исправлен кэш данных. Модели не переобучались, submission не менялся, Public не измерялся. Изменения локальные, коммитов после запроса пользователя не создавалось.

## Решение для ближайшей реализации

Предварительный сервисный кандидат — существующий LightGBM Huber с профилями (`LEAN`, архивное имя `lgbm_huber_blr`). Конкурсный ансамбль v2 сохраняется отдельно. Широкий перебор архитектур на этом этапе не нужен: у команды уже есть простой кандидат с близким качеством и работающий CPU-пакет.

Это не утверждение о готовности к промышленной эксплуатации или превосходстве Huber на скрытом тесте. Остались проблемы согласованности прихода, семантики квантилей и данных. Их исправление и повторная проверка важнее расширения ансамбля.

## Что сделано воспроизводимо

Добавлен `scripts/compare_service_models.py`. До расчёта результатов он записывает manifest: commit и локальные изменения, SHA-256 исходных данных/прогнозов/моделей/кода, версии библиотек, периоды, калибровочную сетку и инженерный допуск. Непустой каталог результатов не перезаписывается.

- Даты OOF восстановлены по исходному train и `default_folds`. Истинные значения каждого использованного архива полностью совпали с исходными данными в восстановленном порядке маршрутов и горизонтов.
- Конфигурации `LEAN` и сохранённого сервисного пакета совпали. Запись `lgbm_huber_blr` в журнале совпала после исключения настройки числа потоков. В архивах нет встроенных ключей/конфигурации обучения; связь с журналом остаётся ограничением происхождения.
- Подтверждены исходные локальные результаты на 14 датах. Полная таблица в [summary.csv](../reports/colhound/ml/summary.csv).
- Веса ансамбля пересчитаны только по 18–24 октября, затем применены к 25–31 октября. Для каждой одиночной модели отдельно выбран множитель только по предыдущей неделе.
- Дополнительная неделя Huber с профилями, 11–17 октября: score 0.330779. Это уже изученный период. Полного v2 на нём в использованных архивах нет.

## Сравнение на следующей неделе

Оценка 25–31.10.2025, семь начал в 10:30, восемь горизонтов и 1000 маршрутов на каждую дату. Меньше — лучше.

| Вариант | Средний score | WAPE | Средний абсолютный bias |
|---|---:|---:|---:|
| v2, веса выбраны только на предыдущей неделе | 0.329607 | **0.317084** | 0.012523 |
| Huber с профилями, без множителя | **0.327883** | 0.317814 | **0.010069** |
| Обычный Huber, без множителя | 0.329124 | 0.318196 | 0.010928 |
| Tweedie, без множителя | 0.330211 | 0.318425 | 0.011785 |

Сервисная модель выигрывает у хронологически откалиброванного ансамбля в среднем на 0.001724 и на четырёх датах из семи. Её WAPE немного выше: выигрыш итогового score получен за счёт меньшего штрафа за общую сумму. Поэтому нельзя утверждать, что она лучше по всем характеристикам.

Множитель Huber с профилями 0.995, выбранный на прошлой неделе, дал score 0.326710 на следующей. Для обычного Huber множитель ухудшил score с 0.329124 до 0.332067, для Tweedie — с 0.330211 до 0.330823. Общая рекомендация «всем моделям нужна калибровка» не подтверждается. Для прототипа пока сохраняем исходный Huber без изменения пакета; успешный множитель одной недели не принимаем как универсальный.

Обе недели уже участвовали в разработке моделей. Эта проверка соблюдает направление подбора коэффициентов во времени, но не создаёт нового независимого holdout. Реестр известного использования периодов: [validation_windows.md](validation_windows.md).

## Эксплуатация и корректность

Сохранённая модель на CPU проверена на исходной последней отсечке, без кэша панели. Полные измерения и окружение: [runtime.json](../reports/colhound/ml/runtime.json), [manifest.json](../reports/colhound/ml/manifest.json).

На двух успешных замерах с четырьмя потоками:

- 8 моделей LightGBM, сервисный пакет около 12 МБ.
- Предсказание 1000 маршрутов: 2.79–3.13 секунды, по три запуска в каждом замере.
- Восстановление симулированного состояния склада за сутки: 21–26 секунд.
- Сумма стадий холодного цикла: 30–36 секунд, без HTTP и LLM.
- Прогноз совпал с архивным `lean_test.npy` без различий. Повторная загрузка моделей дала побитно тот же прогноз.
- Пиковая память всего процесса аудита — около 1.65 GiB; это не изолированная память inference, поскольку процесс также держал проверочные массивы.

Эти измерения относятся к локальной машине и одному снимку; время заметно меняется между запусками. Финальный повтор после исправления кэша записан в runtime.json: холодный цикл 36.00 секунды, dock replay 25.57 секунды. Время ансамбля этим запуском не измерялось, поэтому численный выигрыш скорости относительно него не заявляется.

Проверка снимка подтвердила **два нарушения монотонности накопленного прихода**. На этом снимке точечный прогноз лежит внутри p10/p90, но поле `p50` всё ещё содержит сырой Huber-прогноз, а не откалиброванную медиану. Последнее — семантическая проблема даже при отсутствии пересечений диапазона.

## Исправление кэша

В `src/rwb/data.py` кэш панели теперь связан с SHA-256 исходного train и версией формата. При изменении train, устаревшем формате или повреждении кэша панель восстанавливается. Test каждый раз читается заново. Новый кэш записывается атомарной заменой, незавершённый временный файл убирается. `cache=False` продолжает работать без записи.

Регрессионные проверки охватывают изменение train при сохранённом mtime, повторное использование корректного кэша с новым test, старый формат, повреждённый NPZ/ZIP и запуск без кэша. Все 40 тестов проекта прошли. Модельные артефакты и исходные Parquet не менялись.

## Воспроизведение в PowerShell

Из корня репозитория, после установки доступного окружения проекта:

```powershell
$env:OMP_NUM_THREADS = '4'
$env:OPENBLAS_NUM_THREADS = '4'
$env:MKL_NUM_THREADS = '4'
python scripts/compare_service_models.py --output .local/colhound/reproduce_ml --benchmark --threads 4
New-Item -ItemType Directory -Path .local/colhound -Force | Out-Null
python -m pytest tests -q -p no:cacheprovider --basetemp=.local/colhound/reproduce_tests
```

Для каждого повторного запуска аудита нужен новый пустой каталог. Проверенный текущий интерпретатор: `D:/Development/python_programming/Case_Champ_RWB/.venv/Scripts/python.exe`, Python 3.12.4. Фактические версии пакетов записаны в manifest; это не чистая установка закреплённого Python 3.14-окружения команды.
