# Кейс RWB: «Отгрузки без простоев»

Структурированная версия технического задания. Источник: [страница кейс-чемпионата WB Space](https://wbspace.wb.ru/competitions/kejs-chempionat), прочитанная в авторизованной вкладке Safari **6 ноября 2026 года**. Дополнительные уточнения взяты из приложенного организаторами [baseline](../data/reference/baseline.ipynb).

## 1. Бизнес-задача

Заранее прогнозировать объёмы будущих отгрузок со складов на основе истории и внешних факторов. На основе прогноза система должна позволять определять время вызова машины.

Ожидаемый эффект, заявленный организаторами:

- меньше простоев и дефицита транспорта;
- меньше издержек на избыточный автопарк;
- стабильная работа складов в пиковые периоды.

В предоставленных файлах нет вместимости машин, времени подачи, времени погрузки, стоимости простоя или текущего складского остатка. Поэтому проверяемый результат соревнования — прогноз, а расчёт времени вызова машины требует дополнительных параметров и допущений.

## 2. Входные данные

| Поле | Описание организаторов | Где есть |
|---|---|---|
| `route_id` | Уникальный идентификатор маршрута | Train, test |
| `timestamp` | Момент времени | Train, test |
| `status_1`, `status_2`, `status_3` | Количество товаров данного маршрута, прошедших этапы обработки на текущем складе за последние 30 минут | Train |
| `status_4`, `status_5`, `status_6` | Количество товаров, идущих на текущий склад, прошедших этапы обработки на предыдущем складе за последние 30 минут | Train |
| `target_1h` | Объём товаров, отгруженных по маршруту за последний час | Train |
| `id` | Идентификатор строки для сопоставления предсказания | Test |

Тест не содержит статусов и целевой переменной. Для каждой его строки требуется предсказание `target_1h`.

На странице в абзаце о формате посылки упомянут `test.csv`, но фактически предоставлен `test_solo_track.parquet`. Для ключей и времён используем реальный Parquet.

## 3. Горизонт прогноза

Уточнение из текста baseline: **8 следующих точек по 30 минут после конца train для каждого маршрута**. Это горизонты от +30 минут до +4 часов.

Проверка реальных файлов подтвердила:

- последнее известное состояние — `2025-11-01 10:30:00`;
- тестовые времена — `2025-11-01 11:00:00` … `14:30:00`;
- 1000 маршрутов × 8 времён = 8000 предсказаний.

Времена в файлах не содержат часового пояса. Даты наблюдений относятся к 2025 году; само соревнование проходит в 2026 году.

`target_1h` — объём за час, заканчивающийся в соответствующий момент времени. Шаг наблюдения при этом равен 30 минутам. Следовательно, соседние часовые окна перекрываются: их нельзя без дополнительных условий складывать как независимые получасовые отгрузки.

## 4. Метрика

На платформе используется **WAPE + |Relative Bias|**; меньше — лучше:

\[
\operatorname{score} =
\frac{\sum_i |\hat y_i-y_i|}{\sum_i y_i}
+\left|\frac{\sum_i\hat y_i}{\sum_i y_i}-1\right|.
\]

Код, приведённый на странице:

```python
class WapePlusRbias:
    """Calculates as WAPE + Relative Bias."""

    def calculate(self, y_true: np.ndarray, y_pred: np.ndarray) -> float:
        wape = (np.abs(y_pred - y_true)).sum() / y_true.sum()
        rbias = np.abs(y_pred.sum() / y_true.sum() - 1)
        return wape + rbias
```

Следствия для решения:

- оцениваются и ошибки отдельных точек, и суммарное завышение/занижение;
- метрика вычисляется по всем оцениваемым строкам вместе, а не как среднее метрик маршрутов;
- по пояснению baseline, Public и Private части оцениваются отдельно; способ их разбиения в изученных материалах не указан;
- при сравнении моделей необходимо отдельно сохранять WAPE, signed Relative Bias, его модуль и итоговый score;
- в исходной формуле нет обработки нулевой суммы фактов. При собственной валидации нужно проверять, что знаменатель положителен.

## 5. Формат результата

CSV строго с двумя колонками:

```csv
id,y_pred
0,107240.1694072957
1,138942.26677831585
```

Значения выше взяты из предоставленного примера, это не фактические ответы теста.

Требования из страницы и baseline:

1. Одна строка на каждый `id` теста.
2. Заголовок `id,y_pred`, без дополнительной колонки индекса.
3. Все `id` теста присутствуют ровно один раз.
4. Нет пропущенных предсказаний.

Для собственного пайплайна дополнительно проверяем конечность и неотрицательность прогнозов: это соответствует смыслу объёма и обработке прогнозов в baseline. Явное правило платформы о допустимости отрицательных значений на прочитанной странице не сформулировано.

Предоставленный CSV хранится локально как `data/reference/sample_submission.csv` (в Git его нет). Он подтверждает формат, но не задаёт качество модели и не содержит ground truth.

## 6. Baseline организаторов

Файл `baseline.ipynb` закреплён в разделе «Ноутбуки». Он показывает загрузку данных, построение будущих таргетов, обучение Ridge и формирование посылки. [Оригинал без изменений](../data/reference/baseline.ipynb) хранится вместе с прочими исходными материалами; его SHA-256 указан в манифесте.

## 7. Даты и общие правила

На странице платформы отображались:

| Событие | Дата и время |
|---|---|
| Начало соревнования на платформе | 06.11.2026, 10:40 МСК |
| Завершение соревнования на платформе | 13.11.2026, 20:45 МСК |
| Даты хакатона в опубликованном положении | 12–13.11.2026 |
| Окончание регистрации команд в положении | 11.11.2026, 23:59 МСК |

Краткое содержание положения и неоднозначности находятся в [отдельном файле](source/competition-rules.md). В частности, использование нейросетей требуется указать в финальной презентации с ресурсами и техниками генерации.

В ранее предоставленной общей презентации были отдельные сроки паспорта и заочного отбора. Дедлайн посылок платформы не заменяет автоматически эти сроки. Актуальный календарь и применимость общих требований к RWB необходимо сверить у организаторов.

## 8. Открытые вопросы

- Лимит посылок, количество финальных решений и правило их выбора.
- Как устроено разбиение Public/Private.
- Допустимость и ограничения внешних данных, обмена решениями и использования предобученных моделей.
- Точные этапы `status_1…6`, единица объёма, часовой пояс и происхождение/анонимизация данных.
- Дополнительные параметры для расчёта времени вызова машины и критерий оценки этой части.
- Названия четырёх критериев жюри: в положении приведены только веса 30/30/15/25.
- Согласование разных дат платформы, положения и общей презентации.

Страница содержит общую фразу о внешних факторах, но она не устанавливает подробные правила использования внешних датасетов. Связать анонимный `route_id` с погодой или географией по предоставленным файлам нельзя.
