# Ridge с историей таргета и календарём

## Условия сравнения

Использован тот же [протокол временной валидации](validation.md): 25–31.10.2025, начало в 10:30, восемь получасовых шагов, 1000 маршрутов. Сравниваются средние значения официального score по семи окнам, меньше — лучше.

Сохранены `alpha=4`, `solver=lsqr`, `tol=1e-6`, 14 дней обучающих source timestamps, отсутствие сэмплирования и обрезание отрицательных прогнозов до нуля. Все четыре Ridge используют ровно **673 000 обучающих строк на окно** и одинаковые будущие таргеты. Доступной истории хватает для недельного лага, поэтому строки из-за новых признаков в этих окнах не теряются.

Прогнозы исходного Ridge и четырёх простых моделей полностью совпали с предыдущим сохранённым прогоном. Новые настройки по результатам сравнения не подбирались. Эти семь окон уже использовались при разработке, поэтому это сравнение признаков, а не независимая финальная оценка.

## Признаки

Варианты накапливают признаки последовательно:

| Вариант | Добавление |
|---|---|
| `ridge_status` | Шесть статусов и категория маршрута |
| `ridge_lags` | Значения `target_1h` со сдвигами 0, 1, 2, 3, 6, 12, 48, 336 получасовых шагов |
| `ridge_rolling` | Дополнительно средние таргета за последние 6, 12, 48 точек — 3, 6, 24 часа |
| `ridge_calendar` | Дополнительно получасовой слот суток и день недели исходного момента, оба через one-hot |

Лаг 0 — известное значение таргета в исходный момент, а не будущий ответ. Скользящие средние включают этот момент и только предыдущие точки. Все числовые признаки стандартизуются по fit-части; категориальные кодируются по ней же. У Ridge остаются восемь отдельных выходов для восьми горизонтов.

Признаки обучающей строки ограничены её собственным source timestamp, а не только общим началом проверочного окна. Это важно: даже уже известные на момент валидации значения нельзя подставлять из будущего относительно обучающего примера. Тесты проверяют это заменой всех более поздних значений, а также отдельно проверяют неизменность прогнозов при изменении будущего проверочного интервала.

## Результаты

| Модель | Средний score | Стандартное отклонение | Окон лучше исходного Ridge |
|---|---:|---:|---:|
| Исходный Ridge | 0,355771 | 0,012049 | — |
| + лаги | 0,347806 | 0,011600 | 7 из 7 |
| + лаги и средние | 0,345438 | 0,013641 | 7 из 7 |
| + лаги, средние и календарь | **0,338864** | 0,011427 | 6 из 7 |

Полный вариант улучшил средний score относительно исходного Ridge на **4,75%**. Он лучший среди сравниваемых моделей на пяти окнах; на двух лучшим оказался вариант с лагами и средними. 29 октября полный вариант уступил исходному Ridge: 0,362052 против 0,332348. Улучшение среднего не означает улучшение на каждой дате.

На горизонте +30 минут средний score полного варианта составил 0,277110 против 0,337488 у исходного; на +4 часа — 0,375742 против 0,401638. На отдельных промежуточных горизонтах полный вариант оказался хуже, что видно в подробной таблице.

Результаты: [summary.csv](../results/ridge_features/summary.csv), [по окнам](../results/ridge_features/folds.csv), [по горизонтам](../results/ridge_features/by_horizon.csv), [границы fit](../results/ridge_features/training_audit.json), [конфигурация и SHA-256](../results/ridge_features/metadata.json).

Дополнительный pooled score полного варианта равен 0,328869, но при объединении окон суммарный bias может компенсироваться. Первичным результатом остаётся **средний score 0,338864**. Ни одно из этих значений не является score Public/Private leaderboard.

## Воспроизведение

```bash
python scripts/run_backtest.py --origin-count 7 --origin-time 10:30 --train-days 14 --alpha 4.0 --ridge-features status lags rolling calendar --output .local/runs/ridge_features
python scripts/plot_backtest.py --run-dir .local/runs/ridge_features
python -m pytest -q --cov=rwb_forecasting --cov-branch --cov-report=term-missing
```

Подробные прогнозы и график остаются локально в `.local/runs/ridge_features/`. В Git включены код, тесты и агрегированные результаты.

## Файл для платформы

```bash
python scripts/make_submission.py --feature-set calendar
```

Команда заново обучает полный вариант от последнего факта train — `01.11.2025 10:30`. Сохраняется то же 14-дневное окно sources; самые поздние обучающие labels заканчиваются в 10:30. Прогнозы на 11:00–14:30 сопоставляются с `id` реального test по маршруту и времени.

Готовый локальный CSV — `submissions/ridge_calendar.csv`, параметры и контрольные суммы — `submissions/ridge_calendar.metadata.json`. Проверяются 8000 уникальных ключей теста, две колонки `id,y_pred`, конечность и неотрицательность значений. Создание файла не загружает его на платформу. Подробнее: [submissions/README.md](../submissions/README.md).
