# Сравнение прогнозных моделей

## Протокол

Целевая метрика — `WAPE + |Relative Bias|`, меньше лучше. Основной результат — арифметическое среднее score отдельных четырёхчасовых окон. В каждом окне проверяются все 1000 маршрутов и восемь получасовых горизонтов, 8000 прогнозов.

Для поиска использованы 25–31.10.2025, начало каждого прогноза в 10:30. Проверены 12 конфигураций в двух раундах; исходный `ridge_calendar` оставлен неизменным. По минимальному среднему score выбран один вариант — `hgb_direct_norm_advanced`. Его конфигурация и исходный код зафиксированы до открытия контрольных результатов.

Контроль — 18–24.10.2025, тоже 10:30 и четыре часа вперёд. Эти окна не использованы для выбора кандидата. Они идут раньше исследовательского периода и входят в историю обучения поздних моделей: это дополнительная ретроспективная проверка устойчивости, **не независимый будущий holdout**. После контрольной оценки модель не перенастраивалась. Правило принятия: улучшение среднего score относительно исходного Ridge на обоих наборах.

## Результаты

| Модель | Поиск: средний score | Контроль: средний score |
|---|---:|---:|
| Исходный Ridge с календарём | 0.338864 | 0.338221 |
| Выбранный нормализованный бустинг | **0.334538** | **0.335532** |

Улучшение среднего score: **1.28%** на исследовательских окнах и **0.79%** на контрольных. Выбранная модель лучше исходной на 4 из 7 окон каждого набора. На отдельных датах она уступает: улучшение среднего не означает выигрыш везде.

**Цель среднего score ниже 0,32 за два раунда не достигнута.** Модель принята как небольшое улучшение по заранее зафиксированному правилу. Это результаты локальной исторической проверки, не оценка Public/Private leaderboard.

Полные исследовательские результаты: [все конфигурации](../results/optimization/search_summary.csv), [по окнам](../results/optimization/search_folds.csv). Сравнение выбранной модели с исходной: [поиск](../results/optimization/research/summary.csv), [контроль](../results/optimization/control/summary.csv), [контроль по окнам](../results/optimization/control/folds.csv). ## Выбранная модель

Используются восемь `HistGradientBoostingRegressor`, по одному на каждый горизонт. Для каждого source timestamp доступны только его история и календарные значения. Обучающие labels заканчиваются не позже начала прогнозного окна; ранняя остановка со случайным разбиением отключена.

Признаки: текущие статусы, лаги таргета и скользящие средние; лаги статусов на 1, 2, 3, 6, 12 шагов и их среднее за шесть шагов; недельное среднее таргета; значения таргета в тот же будущий получасовой слот день и неделю назад; среднее, медиана и стандартное отклонение этого слота за семь предыдущих дней; календарь исходного и прогнозируемого времени. Каждая историческая ссылка остаётся не позже своего source timestamp.

Объёмные признаки и обучающий таргет нормируются на известное в исходный момент среднее таргета за последние 24 часа с нижней границей 1000. После прогнозирования возвращается физический масштаб маршрута. Отрицательные прогнозы обрезаются до нуля.

Фиксированные параметры: окно sources 28 дней, шаг отбора sources четыре получасовых точки, 180 итераций, до 31 листа, `learning_rate=0.08`, `l2_regularization=10`, `max_bins=127`, `random_state=42`. На каждом горизонте — 337 000 обучающих строк. Будущие статусы и неизвестные таргеты test не используются.

## Численный решатель линейных кандидатов

Три линейных варианта второго раунда полностью пересчитаны с прямым решением Ridge через блоки матрицы Грама. Математическая задача остаётся прежней: сумма квадратов ошибок с L2-штрафом на коэффициенты и свободным intercept. Признаки, alpha и обучающие окна не изменялись.

Строгая проверка совпадения с приближённым `LSQR(tol=1e-6)` **не прошла**: на проверенном окне максимальная разница score достигла 0,000105. Поэтому совпадение прогнозов не заявляется: старые частичные результаты не смешаны с новым полным прогоном. Смена решателя отмечена в конфигурациях и audits. Исходный `ridge_calendar` и глобальные линейные модели первого раунда сохраняют LSQR; вариант с отдельными коэффициентами маршрутов с самого начала использовал отдельное решение через матрицы Грама.

## Воспроизведение

```bash
python scripts/run_comparison.py --split research --output .local/reproduce/research
python scripts/run_comparison.py --split control --output .local/reproduce/control
python scripts/run_comparison.py --all-research-models --output .local/reproduce/all_candidates
python scripts/make_candidate_submission.py
python -m pytest -q
```

Первая команда сравнивает исходный Ridge и выбранную модель; третья повторяет все исследовательские конфигурации и требует больше времени. Существующие непустые каталоги результатов не перезаписываются. Подробные прогнозы остаются локально; в Git включены код, конфигурации и агрегированные результаты.

CSV выбранной модели создаётся в `submissions/hgb_direct_norm_advanced.csv`, параметры и контрольные суммы — в соседнем `.metadata.json`. Проверяются точные ключи test, две колонки `id,y_pred`, 8000 уникальных IDs, конечность и неотрицательность прогнозов. Создание файла **не отправляет его на платформу**. Оценка скрытого теста неизвестна.
