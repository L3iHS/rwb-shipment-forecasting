## 08.11.2026 — первый ML-аудит и актуальность кэша

**Ограничение пользователя:** работать локально в `Colhound`, не создавать коммиты без разрешения. После `ff5d380` коммитов, stage/push и отправки на платформу не выполнялось.

**Сделано:**

- Добавлены `src/rwb/model_audit.py`, `scripts/compare_service_models.py`, тесты расчёта метрик/калибровки и реестр ранее использованных окон `validation_windows.md`.
- До расчёта записан manifest с хешами исходных данных, сохранённых прогнозов, модели и кода, окружением и хронологическим протоколом.
- Архивные истинные значения сверены с исходным train. Проверено соответствие конфигураций сервиса и проверенного Huber.
- Веса ансамбля выбраны по 18–24 октября и оценены на 25–31 октября. Score Huber с профилями / ансамбля: 0.327883 / 0.329607; Huber выиграл на 4 из 7 дат, прежде всего благодаря меньшему bias. Новый независимый holdout не заявляется.
- Измерен CPU-пакет, проверены совпадение с архивным прогнозом и повторная загрузка. Выявлены два случая уменьшения накопленного прихода; исправление пока не внесено.
- Исправлен кэш `data.py`: SHA-256 train, версия формата, восстановление старого/повреждённого кэша, атомарная запись; test читается заново. Базовая ML-модель, её коэффициенты и исходные датасеты не менялись.
- Выводы и команды записаны в [ml_audit_results.md](ml_audit_results.md). Финальные таблицы/измерения — `reports/colhound/ml/`.

**Проверка:** `python -m pytest tests -q -p no:cacheprovider --basetemp=.local/colhound/test_tmp_03` — 40 passed. Исполняемый аудит проверяет точное соответствие архивов исходным данным и повторную загрузку пакета. После исправления кэша выполнен финальный повтор: manifest имеет статус complete; все его хеши кода/входов/выходов сверены с текущими файлами. Предсказание занимает 2.79–3.13 секунды, полный холодный цикл 30–36 секунд по двум замерам; сохранение/загрузка не изменяет прогноз. `git diff --check` и проверка локальных ссылок документации прошли.

**Обнаруженные технические особенности:** первый тестовый запуск потребовал создать родительский каталог pytest. В первом benchmark изменение параметров file-loaded LightGBM через `reset_parameter` вызвало Windows access violation; benchmark исправлен передачей `num_threads` непосредственно в predict без изменения модели. Неудачный запуск сохранён в `.local/colhound/audit_failed_native_threads/`, первый успешный до исправления кэша — в `.local/colhound/audit_before_cache_fix/`. Установка новых пакетов не требовалась.

**Ограничения и следующий шаг:** кандидат Huber выбран предварительно; квантильная семантика, согласованность прихода и полнота проверок данных ещё требуют работы. Прикладной цикл существенно дольше одного предсказания из-за dock replay. Агент и фронт на этом этапе не изменялись, разработчику агента сообщения не отправлялись.

## 08.11.2026 — реализация следующего этапа, сервис v2

**Сделано:**

- Добавлен `flows.py`: согласование часовых прогнозов с неотрицательными получасовыми потоками. Сохранён исторический метод для сравнений, исходный прогноз модели не меняется.
- `service.py` разделяет point_forecast и p50, калибрует поток и сумму сети отдельно, сохраняет версионированный пакет с происхождением калибровки. Старый пакет не перезаписывается.
- Усилены проверки истории, неизвестных маршрутов, нечисловых/пропущенных статусов и доступности сезонного fallback. У fallback диапазоны не выдаются за откалиброванные.
- Выявлено пересечение последних семи rolling-окон калибровки с будущими оценочными метками. Они исключены; добавлен регрессионный тест границы.
- `snapshot.py` создаёт общий снимок с идентификаторами данных/кода/моделей/калибровки/сценария/отчёта, атомарным кэшем и проверкой контрольной суммы. Добавлены пять Python-функций для агента, включая пересчёт сценария.
- Pipeline, экспорты и пульт используют снимок. Исправлены подписи и неправильная агрегация диапазонов сети. Добавлен текущий notebook service_v2; исходный notebook помечен историческим.
- Добавлены validate_service_v2.py, prepare_service_v2.py, verify_service_v2.py и Node.js smoke check пульта. Подробный отчёт — [service_v2_results.md](service_v2_results.md).
- Добавлен requirements-service.txt с пятью фактически установленными runtime-зависимостями CPU-сервиса; PyTorch/XGBoost для этого пути не нужны. Чистая установка не проверялась.

**Результаты:** старый/новый WAPE накопления 0.182371/0.181725; уменьшающихся накоплений 1854/0; покрытие 80%-диапазона 80.333%/80.340%; потери базовой симуляции 20.252/20.226 минуты на машину. Покрытие сети 87.348% при номинальных 80% отражает консервативность на этом периоде. Нового независимого holdout или Public нет.

**Проверки:** 63 passed. Сквозной запуск проверил 8000 строк, совпадение конкурсного point-экспорта с архивной моделью, совпадение функций/CSV и общий snapshot ID. Первый CLI-прогноз 13.29 с, повтор 4.65 с с cache_hit=True; пульт 4.82 с. Node.js исполнил рендер первой/последней карточки и случая недоступных диапазонов, без NaN/undefined. Полноценная браузерная визуальная проверка не выполнялась. Результаты и манифесты — reports/colhound/service_v2; промежуточные версии сохранены в .local/colhound.

**Границы:** реальные отгрузки/модели/конкурсные CSV не менялись. Пакет service_v2 и снимки локальные и исключены из Git; инструкция восстановления записана. Агент другого участника и HTTP ещё не подключены. Дальнейшие задачи — HTTP-интеграция, интерфейс/чат, паспорт. Всё в Colhound без новых коммитов/stage/push.
