# Пульт диспетчера: устройство

Идея и границы — `docs/ideas/dispatcher-console.md`. Здесь — как пульт устроен и что должен уметь бэкенд ассистента.

## Состав

```
scripts/pipeline.py export  ->  frontend/public/board.json  ->  frontend/ (React)  ->  frontend/dist/
                                         \-> backend/ (FastAPI: /api/agent + раздача frontend/dist)
```

- `pipeline.py export` строит тот же набор данных, что вшивается в `outputs/dispatch_board.html`, и пишет его в JSON.
- `frontend/` — React 18 + TypeScript + Vite, Tailwind, Motion для переходов; графики нарисованы в SVG вручную (`frontend/src/components/charts.tsx`), шрифты Sofia Sans (три ширины) и Martian Mono лежат в сборке. Читает `board.json` при загрузке. Цвета, типографика и правила движения — дизайн-система «Ночная смена», токены в `frontend/src/index.css`.
- `backend/` — FastAPI: `app.py` (маршрут `POST /api/agent`, Claude с функциями, лимит запросов, раздача собранного фронта) и `tools.py` (функции ассистента поверх `board.json`).
- `Dockerfile` в корне собирает фронт и запускает бэкенд в одном контейнере на порту 8000.

Запуск:

```bash
cd frontend && npm install && npm run build
cd ../backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app:app --port 8000
```

Пульт открывается на `http://localhost:8000`. Ключ Claude — в `backend/.env` (образец `backend/.env.example`); без него ассистент отвечает на типовые вопросы сам. Данные пульта обновляет `python scripts/pipeline.py export`. Для разработки фронта — `npm run dev` в `frontend/` (порт 5173, `/api` проксируется на 8000).

Контейнер:

```bash
docker build -t rwb-dispatcher . && docker run -p 8000:8000 --env-file backend/.env rwb-dispatcher
```

## Данные `board.json`

Единица объёма — товары. Шаг — 30 минут, `now` — момент прогноза (последняя точка истории).

| Поле | Что это |
|---|---|
| `now`, `step_min`, `hist_n` | момент прогноза, шаг, сколько точек истории у каждого ряда |
| `model` | `trained_until`, `lib`, `objective`, `lead_h` (подача машины), `fill_hours` (кузов в часах среднего потока), `max_wait_h`, `risk` |
| `network` | `hist` — сумма `target_1h` по сети за 16 шагов; `p50`, `lo`, `hi` — прогноз сети на 8 шагов и диапазон 10–90 % |
| `routes[]` | по маршруту: `id`, `cap` (вместимость кузова), `bl` (груз у ворот в кузовах), `way` / `dock` (машин в пути / у ворот), `call` (шагов до вызова, 0 — сейчас, −1 — не нужен в горизонте), `h` (история `target_1h`), `p10` / `p50` / `p90` (прогноз `target_1h`), `c50` / `c90` (накопленный приток к воротам за 1..8 шагов, медиана и осторожный сценарий), `cr` (приток, по которому правило решает о вызове: откалиброванная медиана) |
| `monitor[]` | журнал качества проверочной недели: `day`, `wape`, `bias`, `cov` (попадание в 80 % диапазон) |
| `alerts[]` | тревоги монитора |
| `backtest` | `sensitivity` — потери на машину (мин) для правил при разных `lead_h` и `fill_hours`; `per_day` — машины, простой, ожидание, недогруз по правилам; `intervals` — заявленное и фактическое попадание; `point` — метрика; `week` — даты недели |

Правило вызова в браузере (`frontend/src/plan.ts`, `backend/tools.py`) повторяет `rwb.dispatch.call_plan`: следующая машина нужна, когда груз у ворот плюс приток покрывают на кузов больше, чем уже вызвано; вызывать её нужно за время подачи до этого момента. По `cr` при исходной подаче результат совпадает с полем `call` у всех 1000 маршрутов.

## Ассистент

### Контракт

```
POST /api/agent
{
  "messages": [{"role": "user" | "assistant", "content": "..."}],
  "view": {"tab": "shift", "route": 471 | null, "lead_h": 1, "risk": "p50" | "p90", "called": {"485": 1}}
}
->
{
  "reply": "1–3 предложения с числами только из функций",
  "actions": [Action, ...],
  "tools": [{"name": "route_status", "args": {"route_id": 471}}]
}
```

`Action` — что пульт сделает после ответа:

| `type` | поля | эффект |
|---|---|---|
| `open_route` | `id` | открыть карточку маршрута |
| `filter` | `value`: `now`, `hour`, `jam`, `all` | фильтр очереди |
| `scenario` | `lead_h`: 0.5, 1, 2; `risk`: `p50`, `p90` | пересчитать очередь при другом времени подачи и сценарии |

### Отметка «Вызвал»

Кнопка в карточке маршрута (или Enter в очереди, стрелки выбирают строку) записывает вызов машины в журнал смены. «Вызвать всем» под заголовком вызывает сразу все машины, которые правило просит сейчас: по маршруту столько, сколько нужно, чтобы он перестал быть срочным. Каждый вызов считается ещё одной машиной в пути, поэтому правило само пересчитывает следующий вызов маршрута: он уходит из «Сейчас» или остаётся, если груза уже больше, чем на вызванные машины.

Что изменилось, видно на графиках: на общей оси пунктирный контур показывает столбец до вызовов, зачёркнутое число над ним прежнее значение, а по дорожке под столбцами машины едут от «сейчас» до времени прибытия. На графике ворот каждая вызванная машина отмечена своей линией уровня, пунктир «нужна ещё машина» поднимается на следующий.

Отменить можно последний шаг целиком (один вызов или «вызвать всем») в строке прогресса и последний вызов маршрута в его карточке. Журнал живёт только в памяти страницы: перезагрузка возвращает пульт к исходному прогнозу.

Пульт передаёт журнал ассистенту в `view.called` (`{"485": 1}`: номер маршрута и число машин), и функции бэкенда считают по тем же маршрутам, что и экран.

### Функции (инструменты модели)

Те же, что в плане защиты (`docs/defense.md`). Работают поверх `board.json`; модель данных напрямую не видит.

| Функция | Аргументы | Возвращает |
|---|---|---|
| `route_status` | `route_id` | когда вызывать, груз у ворот, вызванные машины, история за 8 ч, прогноз с диапазоном, накопление к воротам |
| `find_routes` | `condition`: `call_now`, `call_within_hour`, `waiting_without_truck`, `low_confidence`; `limit` | список маршрутов с ключевыми числами |
| `network_summary` | — | вызовы сейчас и в течение часа, новых машин до конца горизонта, объём за 4 ч, пик сети |
| `what_if` | `lead_h`, `risk` | пересчёт очереди: сколько вызовов сейчас, сколько изменилось, какие маршруты |
| `evidence` | — | потери на машину по правилам, попадание диапазонов, журнал качества |

Функции есть в двух копиях с одинаковыми числами: `backend/tools.py` — для модели, `frontend/src/tools.ts` — для брифинга и ответов без модели (если бэкенд недоступен или нет ключа, пульт отвечает на типовые вопросы сам). Действия пульта бэкенд выводит из вызванных функций: `route_status` открывает маршрут, `find_routes` ставит фильтр, `what_if` меняет сценарий, `evidence` открывает проверку.

### Требования к бэкенду

- Модель — Claude (`claude-sonnet-5-5`, усилие `low`, переменная `MODEL`), официальный SDK `anthropic`. Включены серверные fallbacks (`fallbacks: "default"`): если модель откажется отвечать, запрос сам уйдёт на запасную модель.
- Ключ только в окружении сервера (`ANTHROPIC_API_KEY` или `backend/.env`), в браузер не попадает. Адрес API зашит (`https://api.anthropic.com`), поэтому `ANTHROPIC_BASE_URL` из окружения ключ не получит. Без ключа `/api/agent` отвечает 503.
- Ссылка публичная, поэтому у каждого вопроса есть потолок стоимости: модель видит последние 8 сообщений (не больше 6000 знаков), отвечает не длиннее 1024 токенов, делает до 4 обращений (на последнем функции запрещены) и до 4 функций за раз, на вопрос не больше 45 секунд; повторов при ошибке API нет, перегрузка сразу даёт 503. Длинные прошлые ответы обрезаются до 1000 знаков, а не отклоняются.
- Лимиты: 30 вопросов за 10 минут с одного IP (`RATE_PER_10MIN`), 300 вопросов в час на всех (`RATE_PER_HOUR`), одновременно не больше 4 вопросов (`AGENT_CONCURRENCY`), остальные сразу получают 503 и не занимают сервер. Запрос к `/api/` не больше 64 КБ. На хостинге за прокси нужно задать `FORWARDED_ALLOW_IPS` (адрес прокси), иначе все посетители выглядят как один IP. Для ключа в Console Anthropic стоит поставить лимит расходов: он держит траты при любой ошибке в коде.
- Отказ бэкенда пульт показывает причиной под ответом без модели («Ответ без языковой модели. Слишком много вопросов…»).
- Системный промпт: по-русски, 1–3 предложения, числа только из результатов функций; решение о вызове принимает правило, ассистент его объясняет; на посторонние вопросы отвечает одной фразой.
- Данные пульта уходят в API Anthropic. В плане защиты ассистент на открытой модели внутри компании; для демо выбран Claude.

## План реализации

Каждый шаг — отдельный проверяемый кусок: после него пульт открывается и показывает что-то новое. Числа сверяются со старой доской `outputs/dispatch_board.html`, которая строится из тех же данных.

### Структура

```
frontend/
  public/board.json          данные, пишет pipeline.py export
  src/
    main.tsx, App.tsx        загрузка board.json, тема, панель ассистента
    data.ts                  типы board.json и загрузка
    format.ts                объёмы (тыс., млн), время, склонения
    plan.ts                  правило вызова и KPI
    tools.ts                 функции ассистента (копия backend/tools.py)
    brief.ts                 сводка смены и ответы без модели
    motion.ts                параметры анимаций (длительности, пружины)
    components/
      Shift.tsx              единственный экран: главная цифра, смена на одной оси, фильтры, список, карточка
      Buckets.tsx            чипы-фильтры очереди и тревога «груз без машины»
      CallQueue.tsx          список маршрутов
      RouteCard.tsx          решение по маршруту и график «почему»
      WhatIf.tsx             условия расчёта (подача, сценарий прогноза)
      AgentPanel.tsx         ассистент: сводка смены и чат
      Header, Segmented, Ticker, charts
backend/
  app.py                     /api/agent и раздача frontend/dist
  tools.py                   функции ассистента
  requirements.txt, .env.example
Dockerfile
```

### Шаги

Шаги 1–9 сделаны (08.11). Интерфейс переделан по `docs/ideas/console-redesign.md`; 09.11 экран «Почему верить» убран из пульта — его цифры ассистент по-прежнему отдаёт функцией `evidence`. Ответ модели не проверен вживую (нет ключа на машине разработки), образ Docker не собирался.

| # | Что | Готово, когда |
|---|---|---|
| 1 | Каркас Vite + React + TS + Tailwind, загрузка `board.json`, шапка (момент прогноза, модель, подача) и четыре KPI | KPI совпадают со старой доской: вызвать сейчас, новых машин до 14:30, объём за 4 ч, груз без машины |
| 2 | Пульс склада: история сети 8 ч и прогноз 4 ч с диапазоном, отмечены «сейчас» и пик | график совпадает с блоком сети старой доски |
| 3 | Очередь вызовов: сортировка по времени вызова, фильтры «сейчас / в течение часа / груз без машины / все», поиск по номеру | число строк под каждым фильтром совпадает со старой доской |
| 4 | Карточка маршрута: совет («вызвать сейчас / в 12:00 / не нужно»), график отгрузок с коридором 10–90 %, график груза у ворот в кузовах с моментами вызова и прибытия | для 5–10 маршрутов текст и графики совпадают со старой доской |
| 5 | `plan.ts` и «что если»: подача 30 мин / 1 ч / 2 ч, осторожный сценарий (`c90`); очередь пересортировывается с анимацией | при подаче 1 ч и `c50` пересчитанный `call` совпадает с полем `call` у всех 1000 маршрутов |
| 6 | Экран «Проверка на истории»: потери на машину по пяти правилам с переключателями подачи и кузова, машины и недогруз в день, попадание диапазонов, журнал качества по дням | числа совпадают с `reports/service/lean.json` |
| 7 | `tools.ts`, брифинг и панель ассистента: брифинг при открытии, кликабельные числа, подсказки вопросов; без бэкенда отвечает на типовые вопросы локально | брифинг и ответы содержат только числа из функций |
| 8 | Бэкенд `/api/agent`: FastAPI, функции на Python поверх `board.json`, Claude с функциями, лимит запросов; Dockerfile, который собирает `frontend/dist` и отдаёт его вместе с API | контейнер запускается одной командой, ответы бэкенда и `tools.ts` совпадают на 20–30 вопросах |
| 9 | Полировка: переходы между экранами, выезд панели, счётчики KPI, состояние загрузки и ошибки, светлая и тёмная тема | показ по сценарию защиты проходит без заминок |

Шаги 1–7 не зависят от бэкенда и дают полный показ офлайн. Шаг 8 можно делать параллельно с 6–7: контракт и эталонные числа уже зафиксированы выше.

### Как выглядит и путь показа

Устройство экранов, тексты, анимации и путь показа на защите (1:30–3:30) — в `docs/ideas/console-redesign.md`. Коротко: экран «Вызовы» отвечает на вопрос «кому и когда вызвать машину» (решение одной фразой, условия расчёта, нагрузка склада, тревога, полоса «Когда вызывать», список и решение по маршруту); экран «Почему верить» — «с моделью машина теряет 20,3 мин вместо 60» и доказательства. Оранжевый — один насыщенный цвет, синий — только прогноз на графиках. Анимации объясняют изменения (числа досчитываются, полоса перетекает, строки переезжают) и отключаются при `prefers-reduced-motion`; параметры — в `frontend/src/motion.ts`.

### Зависимости

React 18, TypeScript 5, Vite, Tailwind 4 (`@tailwindcss/vite`), `motion`, `recharts`, `lucide-react`. Версии Vite и `@vitejs/plugin-react` подобрать совместимые: первая установка `vite@6` с последним `@vitejs/plugin-react` упала на конфликте зависимостей.
