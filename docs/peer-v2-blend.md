# Сравнение с ансамблем сокомандника v2

Ансамбль v2 состоит из трёх XGBoost, трёх MLP, LightGBM Huber и LightGBM Tweedie. Модели одного семейства усредняются, затем подбираются четыре веса и общий множитель объёма. В исходном ноутбуке сообщён публичный score **0,323**. Предоставленный участником CSV совпал с файлом из репозитория. [Код решения](https://github.com/L3iHS/rwb-shipment-forecasting/blob/91f89c3a5def0fef093e5b1a22376d1531668a63/notebooks/solution_v2.ipynb) · [Прогнозы компонентов](https://github.com/L3iHS/rwb-shipment-forecasting/tree/05b1603e2ec131593a0aedddf142955f3e7699a3/models/oof).

Четырнадцать дат с 18 по 31 октября совпадают с нашей валидацией. Проверены исходные метки, порядок маршрутов, средние трёх seed'ов и соответствие тестовых ID. Повторная сборка v2 из исходных прогнозов компонентов дала те же 8000 значений. Переобучение компонентов для этой проверки не требовалось.

## Сборка CSV

Сохраните исходный `ensemble_v2.csv` как `submissions/teammate_ensemble_v2.csv`. Второй входной файл собирается по [инструкции для недельного прогноза](weekly_latent.md).

```bash
python scripts/make_v2_weekly_blend.py \
  --peer-csv submissions/teammate_ensemble_v2.csv \
  --weekly-csv submissions/weekly_v3_latent_half_shares.csv \
  --test data/raw/test_solo_track.parquet \
  --output submissions/ensemble_v2_weekly50.csv
```

Команда сопоставляет оба прогноза по `id`, вычисляет среднее в единицах исходного объёма и сохраняет 8000 строк. Рядом записываются хеши входов и результата. SHA-256 проверенного CSV — `b09c61d1c096d4b87cafb726546b658a294ac8cf01b990477aa48f2b77ec99fc`.
