# RWB Shipment Forecasting

Решение кейса RWB «Отгрузки без простоев» для кейс-чемпионата Т1, 2026.

[Соревнование WB Space](https://wbspace.wb.ru/competitions/kejs-chempionat) · [Техническое задание](docs/task.md) · [Данные и исходные материалы](data/README.md)

## Задача

По истории 1000 маршрутов спрогнозировать `target_1h` на следующие четыре часа: восемь точек с шагом 30 минут. `target_1h` — объём отгрузок за час, заканчивающийся в соответствующий момент времени.

Метрика — **WAPE + |Relative Bias|**, меньше — лучше. Формат ответа — CSV `id,y_pred`, 8000 строк. Прикладная цель — поддержать решение о времени подачи машины на склад.

## Установка

Проверенное окружение — Python 3.14.6. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/profile_data.py
```

Одна установка включает зависимости проекта, тестов и запуска notebook через JupyterLab. Аудит не изменяет исходники; его отчёты сохраняются локально в `.local/reports/data_audit/`.

## Временная валидация

```bash
python scripts/run_backtest.py --origin-count 7 --origin-time 10:30 --train-days 14 --alpha 4.0
python scripts/plot_backtest.py
python -m pytest -q
```

Сравниваются четыре простых прогноза и Ridge на семи исторических четырёхчасовых окнах без доступа моделей к будущим наблюдениям. Подробные выходные файлы сохраняются локально в `.local/runs/temporal_baselines/`.

Средний score исходного Ridge — **0,3558**, лучшего простого ориентира — **0,4424**. Это локальная проверка, не оценка платформы. [Исходный протокол и результаты](docs/validation.md).

## Ridge с дополнительными признаками

```bash
python scripts/run_backtest.py --ridge-features status lags rolling calendar --output .local/runs/ridge_features
python scripts/plot_backtest.py --run-dir .local/runs/ridge_features
```

На тех же семи окнах добавление лагов таргета, скользящих средних и календаря снизило средний score до **0,3389** — на 4,75% относительно исходного Ridge. [Состав признаков и сравнение](docs/ridge-features.md).

## Готовый CSV для платформы

Новый экспериментальный файл — **`submissions/v3_tweedie_h1_600.csv`**. Это воспроизведение модели Владо: локальный средний score **0,327937** против **0,332149** у `mae_share_mass25`, выигрыш на **11 из 14** дат. На семи контрольных датах score **0,333661** против **0,336162** у `mae_share_mass25` и **0,336857** у `latent_mass_blend50`: выигрыш у обоих на **6 из 7** дат. Публичный результат неизвестен. [Модель, результаты и команды воспроизведения](docs/v3_tweedie_h1_600.md).

```bash
python scripts/run_v3.py submit --config configs/v3_tweedie_h1_600.json \
  --train data/raw/train_solo_track.parquet --test data/raw/test_solo_track.parquet \
  --output submissions/v3_tweedie_h1_600_reproduced.csv
```

Для модели требуется `lightgbm==4.7.0`, включённый в `requirements.txt`. Команда создаёт новый локальный CSV и не отправляет его на платформу.

Лучший подтверждённый публичный результат пока относится к `latent_mass_blend50`:

```bash
python scripts/make_candidate_submission.py --config configs/latent_mass_blend50.json
```

Результат — локальный `submissions/latent_mass_blend50.csv` с колонками `id,y_pred`. По скриншоту участника публичный score — **0,330** против 0,331 у предыдущего гибрида. Средний локальный score на 14 окнах — **0,332570**, на семи дополнительных контрольных окнах — **0,343437** против **0,343906** у исходного гибрида. Модель сохраняет первый горизонт гибрида и перераспределяет остальные прогнозы между маршрутами при сохранении предсказанной суммы. [Устройство и воспроизведение](docs/mass-blend.md).

Новый экспериментальный вариант `mae_share_mass25.csv` создаётся с `--config configs/mae_share_mass25.json`. Его средний локальный score — **0,332149**, публичный результат пока неизвестен. На семи контрольных окнах — **0,343478**, немного хуже `latent_mass_blend50`; устойчивое улучшение не подтверждено. [Результаты перераспределения по долям MAE](docs/mae-shares.md). Предыдущий взвешенный вариант со средним локальным score **0,332322** сохраняется отдельно в `configs/objective_scale1_mass50.json`.

CSV и сопроводительные метаданные исключены из Git; конфигурации моделей сохраняются в `configs/`. [Правила каталога submissions](submissions/README.md). Команда ничего не отправляет на платформу. Предыдущий `latent_ridge_h1_hybrid.csv` воспроизводится с `--config configs/round3.json`.

## Первые два раунда сравнения моделей

После двух раундов и 12 проверенных конфигураций выбран нормализованный бустинг с отдельной моделью для каждого горизонта. Средний score снизился с **0,338864 до 0,334538** на исследовательских окнах. На семи дополнительных контрольных окнах результат — **0,335532 против 0,338221** у прежнего Ridge. Цель среднего score ниже 0,32 пока не достигнута.

```bash
python scripts/run_comparison.py --split research --output .local/reproduce/research
python scripts/run_comparison.py --split control --output .local/reproduce/control
```

Контроль не использовался для выбора модели. Это дополнительные исторические окна, расположенные раньше исследовательского периода; они не заменяют проверку на скрытом тесте платформы. [Протокол, признаки и результаты](docs/optimization.md).

Предыдущий CSV Ridge по-прежнему можно создать командой `python scripts/make_submission.py --feature-set calendar`.

Гибрид выиграл на шести из семи новых контрольных окон. Это средние значения `WAPE + |Relative Bias|` на исторических данных, а не score платформы. Контрольные окна расположены раньше исследовательских; их результаты не использовались для выбора конфигурации. Цель **ниже 0,32 не достигнута**. [Протокол и воспроизведение](docs/round3.md).

Для третьего раунда обязательно указывать `--config configs/round3.json`: значения по умолчанию в CLI относятся к прежнему сравнению. Старый бустинг доступен через `python scripts/make_candidate_submission.py --config configs/comparison.json`.
